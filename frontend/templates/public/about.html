About the Passport Automation System

Software Engineering Lab Project — Architecture, Requirements, and Specifications

1. System Overview & Objective

The Passport Automation System (PAS) is a full-stack web application developed to replace manual, paper-intensive passport issuance procedures with a centralized, transparent, and auditable digital platform.

The system governs applicant registration, multi-step passport requisition form processing, digital document repository storage, double-booking protected appointment scheduling, multi-officer document verification, and progressive real-time status tracking.

2. Three-Tier Architectural Specification

Tier 1: Presentation Layer (Client)

Engineered with HTML5, CSS3 design tokens, and modular vanilla JavaScript. Delivers responsive portals for both citizen applicants and verification officers with zero third-party UI bloat.

Tier 2: Application Layer (Business Logic)

Powered by Python Flask microservices and RESTful API endpoints. Implements Werkzeug cryptographic hashing, session-based role authorization, validation pipelines, appointment slot mutex concurrency, and event-driven notifications.

Tier 3: Database Layer (Data Persistence)

Normalized relational schema (MySQL 8.0 / SQLite dual compatibility) managed via SQLAlchemy ORM. Maintains strict foreign key constraints, cascading policies, and transactional audit trails.

3. Functional Requirements Summary

Module Actors Key Operations
Authentication Applicant, Officer, Admin Secure registration, password hashing (scrypt), role-based session guarding.
Application Lifecycle Applicant 5-Step form wizard, draft saving, document upload, review, sequential ID generation.
Appointments Applicant, Admin Capacity-bounded slot reservation, double-booking mutex lock, appointment slip generation.
Document Verification Passport Officer Per-document inspection checklist, mandatory rejection rationale, approval authorization.
Audit & Reports Administrator State transition history logging, notification dispatching, filterable CSV reports.

Technology Stack

Frontend: HTML5, CSS3, Vanilla JS

Backend: Python 3.12, Flask 3.1

ORM Layer: SQLAlchemy / PyMySQL

Database: MySQL 8.0 / SQLite Dual-Engine

Security: Werkzeug Scrypt, Session Auth

Storage: Isolated Server Filesystem

Viva Quick Fact

Why Three-Tier Architecture?
It decouples presentation (UI) from business logic (rules & validations) and database storage, ensuring independent scalability, maintainability, and enhanced security against direct database manipulation.
